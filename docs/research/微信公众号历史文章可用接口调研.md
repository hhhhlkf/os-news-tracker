# 微信公众号历史文章可用接口调研

> 调研日期：2026-08-04
> 目标：在不使用 Cookie 池、账号轮换、移动端仿冒等绕过风控方式的前提下，核查获取指定微信公众号历史文章的可用通道，并对公开端点做最小、非破坏性验证。

## 结论

> 补充：已经验证“公开微信原文反查 __biz → 生成微信读书公众号阅读页 → 用户登录后请求 web/mp/articles”的通用链路。可交接步骤、ID 编码算法、凭据安全要求和 Sysin 实测参数见[《微信读书获取公众号历史文章方法》](./微信读书获取公众号历史文章方法.md)。该通道依赖正常微信读书网页会话，属于网页内部接口，不应宣称为官方开放 API 或绝对完整历史。

针对当前指定目标**“腾讯技术工程”**，已找到比公众号后台接口更适合生产落地的一手归档源：[腾讯云开发者社区认证账号](https://cloud.tencent.com/developer/user/170434)。该页面自述为“腾讯技术工程事业群官方微信公众号”，其公开 POST 列表接口无登录返回 `code=0, total=1105`。第 1 页最新记录为 2024-08-29，第 56 页最老记录为 2017-06-05；文章镜像页含完整正文，且能找到原始 `mp.weixin.qq.com/s` 来源链接。

因此，当前目标的推荐解决方案是：**用腾讯云官方社区归档接口回填 2017-06-05 至 2024-08-29 的 1105 条历史，再用搜狗/Bing 公开发现补齐 2024-08-29 之后的增量**。这个归档不应宣称为公众号从创建至今的绝对完整历史，但它是目前对该指定目标覆盖最广、无需微信登录且可直接验证的通道。

找到一个与公众号后台 `cgi-bin/appmsg` 不同的可用公开通道：**微信公众号“合集/话题”页 `https://mp.weixin.qq.com/mp/appmsgalbum`**。

它可以在不登录、不携带 Cookie 的情况下返回某个公开合集的文章列表，并通过同路径 `f=json` 请求分页。本次对一个声明有 74 篇内容的公开合集进行了完整的低频度验证：

- 公开 HTML 首屏返回 10 篇；
- 随后 7 次 JSON 分页分别返回 `10/10/10/10/10/10/4` 篇；
- 所有请求均为 HTTP 200、`base_resp.ret=0`；
- 末页 `continue_flag=0`；
- 首屏 10 篇加分页 64 篇，与页面声明的 74 篇一致；
- 返回标题、发布时间、公开文章 URL、`msgid`、`itemidx` 和封面等字段。

这个通道的硬边界是：**它只能取回该公众号主动放入某个合集的文章，不等于公众号全部历史文章**。公众号没有维护合集时，此方法完全不可用。它也不是微信开放平台正式文档承诺的 API，因此应作为“公开合集发现源”，而不是稳定性有 SLA 的通用历史接口。

对自有或明确授权的公众号，正式方案是微信官方 `freepublish/batchget`；对未授权第三方公众号，官方 API 不提供任意账号查询，可在有公开合集链接时使用 `appmsgalbum`，其余情况继续使用搜狗微信搜索等公开发现源做增量补漏。

## 当前目标：腾讯云官方社区归档接口

### 身份与一手性校验

[腾讯云开发者社区 UID 170434](https://cloud.tencent.com/developer/user/170434) 页面返回 HTTP 200，标题为“腾讯技术工程官方号”，页内标注“腾讯技术工程事业群官方微信公众号”。这是腾讯自己的公开社区归档，不是不明来源的第三方数据商。

实测文章[“人人都是 AI 玩家”](https://cloud.tencent.com/developer/article/2448424) 页面返回 HTTP 200 和正文 HTML，页面源码中有 1 个原始 `mp.weixin.qq.com/s` 来源 URL，且其 `__biz=MjM5ODYwMjI2MA==` 与“腾讯技术工程”目标一致。

### 列表接口与实测结果

公开列表端点为：

```text
POST https://cloud.tencent.com/developer/services/ajax/user-center
Content-Type: application/json

{
  "action": "GetUserArticlesBasicInfo",
  "payload": {
    "uid": 170434,
    "pageNumber": 1,
    "pageSize": 20
  }
}
```

浏览器前端实际发出的请求 URL 带有 `action=GetUserArticlesBasicInfo&csrfCode=5381`；本次额外对比验证了无查询参数、只带 `action`、以及 `csrfCode=0` 三种形式，全部无登录返回 HTTP 200、`code=0`、`total=1105`。因此当前调用不依赖会话 Cookie，也不需要固化或伪造 `csrfCode`。

| 页码 | HTTP/业务状态 | 数量 | 首条 | 末条 |
| --- | --- | --- | --- | --- |
| 1 | `200`, `code=0`, `msg=ok` | 20 | `2448424` “人人都是AI玩家”，2024-08-29 | `2425214` “更快更小！ProtoBuf 入门详解”，2024-06-06 |
| 56 | `200`, `code=0`, `msg=ok` | 5 | `1005327` “腾讯许勇：腾讯技术研发正在全面拥抱开源”，2017-06-23 | `1005200` “鹅厂上万节点大规模集群的跨城自动迁移（上）”，2017-06-05 |

返回 `data.total`和 `data.list[]`；列表条目实测含 `id/articleId`、`title`、`summary/abstract`、`picture/coverImageUrl`、`authorId`、`writeTime/updateTime`、标签及交互计数等字段。`writeTime` 为 Unix 时间戳，本文的日期均由该字段转换。

### 针对该目标的落地方案

1. 配置一个 `tencent_cloud_author_archive` 发现源，固定 `uid=170434`，以认证用户页作为身份校验依据。
2. 首次按 `pageNumber=1..56, pageSize=20` 低频回填，以 `articleId` 作为源端唯一键；每页读取后核对 `code=0` 和 `total`，空页或达到 `total` 后停止。
3. 将 `https://cloud.tencent.com/developer/article/{articleId}` 作为稳定镜像 URL，标题、摘要、封面和发布时间直接由列表元数据得到。
4. 在需要正文时再低并发请求镜像文章页；若页面带原始 `mp.weixin.qq.com/s` 链接，另存为 `canonical_source_url`，但不依赖微信正文页必然可访问。
5. 日常增量只查第 1 页，遇到已知 `articleId` 即停。但该归档实测已停在 2024-08-29，因此必须同时保留搜狗 `type=2` 和 Bing `site:mp.weixin.qq.com` 的低频补漏源，用来补齐这一日期之后的文章。
6. 不把腾讯云归档的 `writeTime` 无条件当作微信首发时间；如果正文内能解析微信原始时间，可优先使用并保留两个时间字段以便审计。

此接口是腾讯云开发者社区的公开站内接口，不是腾讯云对外承诺稳定的开发者 API；因此同样要做结构变化检测、有界重试和返回字段容错，但它不依赖微信后台会话，比已限频的 `cgi-bin/appmsg` 更适合当前目标。

## 新通道：公开合集 `appmsgalbum`

### 可直接复现的公开合集

本次使用的微信公开页面为[“📼 音频节目合集”](https://mp.weixin.qq.com/mp/appmsgalbum?__biz=MzIxNDMwMzk4NQ%3D%3D&action=getalbum&album_id=3686768812583485447)。不带 Cookie 请求得到：

| 项目 | 实测结果 |
| --- | --- |
| HTTP 状态 | `200` |
| Content-Type | `text/html; charset=UTF-8` |
| 公众号名 | `主唱死了` |
| 合集名 | `📼 音频节目合集` |
| 页面声明数量 | `74` |
| 首屏文章数 | `10` |
| `continue_flag` | `1` |

首屏数据同时出现在 HTML 卡片和页面的 `window.cgiData` 中。每篇至少可取得 `title`、`create_time`、`url`、`msgid`、`itemidx` 等字段。

首页最后一条为 `msgid=2247485517, itemidx=1`。按微信页面当前使用的分页格式请求下一页：

```bash
curl -sS \
  'https://mp.weixin.qq.com/mp/appmsgalbum?action=getalbum&__biz=MzIxNDMwMzk4NQ%3D%3D&album_id=3686768812583485447&count=10&begin_msgid=2247485517&begin_itemidx=1&f=json'
```

实测返回 HTTP 200 和 JSON，关键结构为：

```text
base_resp.ret = 0
getalbum_resp.article_list = [10 条]
getalbum_resp.continue_flag = "1"
```

第一条已变为更旧的“第53期：Z 时代爵士厂牌……”，`msgid=2247485487, itemidx=1`，证明该请求实际翻到了下一页。继续用每页最后一条的 `msgid/itemidx` 作为游标，直到 `continue_flag=0`，本次取回了全部 74 条。

同时核查了微信页面当前加载的[官方前端脚本](https://res.wx.qq.com/mmbizwap/zh_CN/htmledition/js/album/appmsg/album7f78b5.js)：该资源返回 HTTP 200，源码中直接出现 `appmsgalbum`、`album_id`、`begin_msgid`、`begin_itemidx`、`continue_flag` 和 `is_reverse`，与上述实测分页契约一致。该 JS 资源名可随微信发版变化，实现不应将带 hash 的脚本 URL 作为固定依赖。

通用的当前请求模板是：

```text
GET https://mp.weixin.qq.com/mp/appmsgalbum
    ?action=getalbum
    &__biz={URL_ENCODED_BIZ}
    &album_id={ALBUM_ID}
    &count=10
    &begin_msgid={LAST_MSGID}
    &begin_itemidx={LAST_ITEMIDX}
    &f=json
```

### 建议的项目接入方案

建议将其定义为新的可选发现源 `wechat_public_album`，不替换现有正式来源：

1. 以公开合集 URL 作为必需种子，从中只保存 `__biz` 和 `album_id`，不保存 Cookie、`uin`、`key`、`pass_ticket` 或 `appmsg_token`。
2. 首次请求 HTML 页，校验公众号名、合集名和声明文章数，解析首屏 `articleList`。
3. 用上一页末条的 `msgid/itemidx` 请求 `f=json` 分页；终止条件为 `continue_flag=0`、空页、游标重复、HTTP 403/429、验证页或 `base_resp.ret != 0`。
4. 用 `(__biz, msgid, itemidx)` 作为主去重键，同时规范化文章 URL 为 HTTPS；多个合集之间再按规范化文章 URL 去重。
5. 首次可做有界回填；后续增量只查首页，遇到已知 `msgid/itemidx` 即停，避免每次翻完整个合集。
6. 正文抓取与列表发现解耦，仅低并发请求合集返回的公开文章 URL；如果页面要求在微信客户端打开或出现验证，当次停止，不做会话仿冒或风控绕过。

一个公众号可能维护多个合集，因此完整性的正确表述应是“已配置合集的文章集合”，而不是“该公众号的全部历史”。目前没有发现一个无授权、可用 `__biz` 枚举该号所有合集的正式公开 API，所以合集 URL 不能省略。

## 官方发布记录 API 的真实边界

微信官方已经提供[“获取已发布的消息列表”](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_batchget)：

```text
POST https://api.weixin.qq.com/cgi-bin/freepublish/batchget?access_token=ACCESS_TOKEN
Body: {"offset": 0, "count": 20, "no_content": 1}
```

`count` 取值为 1–20，返回 `total_count`、`item_count` 和 `item[]`。每个发布条目含 `article_id`、`update_time`、`content.news_item[]`；文章字段包括标题、作者、摘要、正文 HTML、封面、URL 和删除状态等。

但它不是“查任意公众号”的 API：

- 普通 `access_token` 需由该账号自己的 AppID 和 AppSecret 取得，见[获取接口调用凭据](https://developers.weixin.qq.com/doc/service/api/base/api_getaccesstoken)。
- `freepublish/batchget` 支持第三方平台代调用，但要使用授权账号的 `authorizer_access_token`，权限集 ID 为 7。
- 微信官方的[代调用接口说明](https://developers.weixin.qq.com/doc/oplatform/Third-party_Platforms/2.0/Before_Develop/call_interface)明确要求：第三方平台先获得该公众号管理员的授权，且公众号自身拥有该接口权限。
- [获取授权账号调用令牌](https://developers.weixin.qq.com/doc/oplatform/openApi/ticket-token/api_getauthorizeraccesstoken)要求第三方平台的 `component_appid`、授权方 `authorizer_appid` 和授权流程产生的 `authorizer_refresh_token`。
- 官方[发布能力概述](https://developers.weixin.qq.com/doc/service/guide/product/publish.html)还注明：2025 年 7 月起，个人主体、企业主体未认证及不支持认证的账号会被回收发布相关接口调用权限。

因此，“支持第三方调用”的准确含义是**经公众号管理员授权后代运营调用**，不是未授权地读取第三方公众号。

`freepublish/get` 也不能枚举历史：它只能用已知 `publish_id` 查询某次发布任务的状态和详情，见[发布状态查询](https://developers.weixin.qq.com/doc/service/api/public/api_freepublish_get)。`freepublish/getarticle` 则需要已知 `article_id`，见[获取已发布图文信息](https://developers.weixin.qq.com/doc/service/api/public/api_freepublishgetarticle)。真正做列表枚举的是 `freepublish/batchget`。

本次仅用缺失和显式无效的探测 token 做无状态验证，没有读取或输出任何真实凭证：

| 请求 | HTTP | 响应结构 |
| --- | --- | --- |
| `POST /cgi-bin/freepublish/batchget` 不带 token | `200` | `errcode=41001`, `access_token missing` |
| 带显式无效的探测 token | `200` | `errcode=40001`, `invalid credential` |

这证明端点在线且认可官方文档的请求结构，但在没有账号授权的前提下不能对任意目标做真实数据调用。

## `profile_ext` 不是公开无会话历史 API

对“腾讯技术工程”的公开账号标识做了两个无 Cookie 最小请求：

1. [`profile_ext?action=home`](https://mp.weixin.qq.com/mp/profile_ext?action=home&__biz=MjM5ODYwMjI2MA%3D%3D&scene=124) 返回 HTTP 200，但响应头 `logicret=-3`，页面标题为“验证”，并提示“请在微信客户端打开链接”。
2. [`profile_ext?action=getmsg`](https://mp.weixin.qq.com/mp/profile_ext?action=getmsg&__biz=MjM5ODYwMjI2MA%3D%3D&f=json&offset=0&count=10&is_ok=1&scene=124) 返回 HTTP 200 JSON，但业务结果为 `ret=-3`, `errmsg="no session"`, `cookie_count=0`。

所以 `profile_ext` 不能作为公开、无认证的历史列表接口。通过 `uin/key/pass_ticket/appmsg_token` 复刻微信客户端短期会话不属于本次可接受方案，本次也没有尝试获取、伪造或轮换这些参数。

## 搜狗微信搜索的当前实测

搜狗微信搜索仍可用于“公开文章发现”，但不是完整历史 API。本次请求[文章搜索 `type=2&query=Hacking Time`](https://weixin.sogou.com/weixin?type=2&query=Hacking%20Time&ie=utf8&page=1)：

- HTTP 200，返回 HTML；
- 第 1 页有 10 个文章卡片；
- 其中 1 条的来源名精确为 `Hacking Time`，标题为“Linux 最新资讯 20260723——COSMIC Epoch 1.4 发布……”；
- 点击搜狗跳转链路能定位到 `mp.weixin.qq.com/s`，但本次环境最终得到微信验证页，因此只能确认搜索卡片元数据，不能声称正文抓取成功。

[公众号搜索 `type=1`](https://weixin.sogou.com/weixin?type=1&query=Hacking%20Time&ie=utf8) 本次也返回 HTTP 200，但页面显示没有相关官方认证订阅号。这说明不能依赖 `type=1` 覆盖所有公众号。

搜狗结果为默认相关性排序，不能保证时间倒序或历史完整性；也可能返回验证码页。它适合低频增量发现，并在项目内按来源名、发布时间和 URL 二次筛选去重；不适合被包装成“指定公众号完整历史”。

## 通道决策表

| 目标场景 | 推荐通道 | 能否枚举 | 凭证/授权 | 完整性 |
| --- | --- | --- | --- | --- |
| 当前目标“腾讯技术工程”历史回填 | 腾讯云 UID 170434 归档接口 | 能，实测 1105 条 | 无登录，腾讯云认证公开账号 | 目标特定镜像，覆盖 2017-06-05—2024-08-29，已停更 |
| 自有、代运营或已明确授权公众号 | `freepublish/batchget` | 能 | 本号 `access_token` 或授权后 `authorizer_access_token` | 已成功发布列表，受账号接口权限限制 |
| 未授权第三方号，且已知公开合集 URL | `appmsgalbum` | 能，按合集分页 | 无 Cookie，以公开 `__biz + album_id` 为种子 | 仅该合集，不是账号全历史 |
| 未授权第三方号，无合集 | 搜狗 `type=2` + 通用搜索引擎补漏 | 不能可靠枚举 | 公开搜索 | 只做增量发现，可能缺失或验证 |
| `profile_ext` 无会话请求 | 不使用 | 否 | 实测 `no session` | 不可用 |
| 公众号后台 `cgi-bin/appmsg` | 不作未授权生产通道 | 受后台会话和风控限制 | 公众平台后台会话 | 已出现 `ret=200013` 限频，不稳定 |

## 最终建议

1. **当前目标首选：**用腾讯云 UID 170434 公开归档接口回填 1105 条，并保留镜像 URL 和原始微信 URL。它是“腾讯技术工程”的目标特定历史镜像，不是通用微信 API，且已于 2024-08-29 停更，之后增量需用搜狗/Bing 补齐。
2. **公开合集可落地：**把 `appmsgalbum` 作为一种“公开合集”来源。用户提供或公开页面发现合集 URL 后，完成首次有界回填和后续首页增量。
3. **最优正式通道：**若目标公众号属于自有或愿意授权的主体，直接接入 `freepublish/batchget`，不再借用公众平台网页后台会话。
4. **其他未授权账号：**保留“搜狗微信搜索 + 公开文章链接 + 通用搜索补漏”的发现模式，明确展示“不保证历史完整”。
5. **不采用：**不通过 Cookie 池、多账号轮换、移动端仿冒、短期 `profile_ext` 会话参数或其他方式绕过微信风控。
