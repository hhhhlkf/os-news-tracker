# 微信读书获取公众号历史文章方法

> 最后验证：2026-08-04
>
> 用途：供后续 agent 接手指定微信公众号的历史文章发现和抓取。
>
> 安全边界：不使用 Cookie 池、多账号轮换、移动端仿冒或风控绕过；登录和验证由用户在正常浏览器中完成。

## 结论

对于已经被微信读书收录的公众号，可以从一篇公开微信原文反查账号的 __biz，将它转换成微信读书 bookId，生成公众号阅读页。用户登录微信读书网页版后，该页面会调用内部列表接口：

~~~text
GET https://weread.qq.com/web/mp/articles?bookId={bookId}&offset=0
~~~

核心映射为：

~~~text
微信原文中的 __biz
    ↓ Base64 解码
公众号数字 ID
    ↓ 添加 MP_WXS_ 前缀
微信读书 bookId
    ↓ 使用当前网页的 ID 编码算法
微信读书公众号阅读页
    ↓ 用户正常登录
历史文章列表接口
~~~

阅读页本身可以无登录返回 HTTP 200，但文章列表需要有效登录态。无登录实测返回：

~~~json
{"errCode": -2010, "errMsg": "用户不存在"}
~~~

这条链路属于微信读书网页内部能力，不是官方开放 API。它只能返回微信读书已经收录的文章，不能宣称是公众号从创建至今的绝对完整历史。

## 完整处理步骤

### 1. 找到目标公众号的一篇真实微信原文

如果只有公众号名称，可先用搜狗微信文章搜索做公开发现：

~~~text
https://weixin.sogou.com/weixin?type=2&query={URL_ENCODED_NAME}&ie=utf8&page=1
~~~

账号身份必须交叉校验：

- 搜索卡片的来源名与目标公众号一致；
- 跳转后落到 mp.weixin.qq.com/s；
- 微信文章页中 #js_name 的显示名与目标一致；
- 标题或正文可与公众号官网、公开镜像等一手来源对应。

搜狗结果的 /link?url=... 不是最终微信 URL。当前跳转页可能把真实 URL 拆成多段 JavaScript：

~~~javascript
var url = '';
url += 'https://mp.';
url += 'weixin.qq.c';
// ...
window.location.replace(url);
~~~

应在同一浏览器上下文中正常跟随跳转，或只拼接页面明文提供的 url 片段。遇到验证码时停止，不自动绕过。

### 2. 从微信原文提取公众号标识

从文章 URL 查询参数或 HTML 中提取：

~~~text
__biz
var biz = "..."
~~~

同时读取以下字段用于校验：

| 字段 | 用途 |
| --- | --- |
| #js_name | 公众号显示名 |
| var user_name | 微信号，常见格式为 gh_xxxxxxxxxxxx |
| var msg_title | 文章标题 |
| var ct | Unix 发布时间 |

__biz 是 Base64 文本。转换方法：

~~~python
import base64

numeric_id = base64.b64decode(biz).decode("ascii")
if not numeric_id.isdigit():
    raise ValueError("invalid __biz")

book_id = f"MP_WXS_{numeric_id}"
~~~

### 3. 生成微信读书公众号阅读页

微信读书路由使用 encryptedBookId，而不是直接放置 bookId。2026-08-04 实测的当前网页编码算法如下：

~~~python
import hashlib


def encode_weread_id(value: str) -> str:
    digest = hashlib.md5(value.encode()).hexdigest()
    encoded = digest[:3]

    if value.isdigit():
        parts = [
            hex(int(value[index:index + 9]))[2:]
            for index in range(0, len(value), 9)
        ]
        value_type = "3"
    else:
        parts = ["".join(hex(ord(char))[2:] for char in value)]
        value_type = "4"

    encoded += value_type + "2" + digest[-2:]
    encoded += "g".join(f"{len(part):02x}{part}" for part in parts)

    if len(encoded) < 20:
        encoded += digest[:20 - len(encoded)]

    encoded += hashlib.md5(encoded.encode()).hexdigest()[:3]
    return encoded
~~~

生成阅读页：

~~~python
reader_url = (
    "https://weread.qq.com/web/mp/reader/"
    + encode_weread_id(book_id)
)
~~~

编码算法不是稳定的公开契约。如果未来阅读页不再触发 web/mp/articles，应重新检查当前微信读书前端 bundle 的实现，不要为单个公众号添加硬编码特例。

### 4. 由用户完成微信读书登录

1. 在普通浏览器中打开 https://weread.qq.com/。
2. 用户自行扫码登录并完成可能出现的安全确认。
3. 在同一个浏览器 profile 中打开生成的公众号阅读页。
4. 打开 DevTools 的 Network 面板，过滤 mp/articles。
5. 确认 offset=0 的请求成功返回文章数据。

当前浏览器请求除 Cookie 外，还可能包含动态请求头 x-wrpa-0。不要手工猜测或写死其值，应复用当前已登录浏览器发出的成功请求。

### 5. 将成功请求安全交给执行 agent

在 Network 中右键成功的 mp/articles 请求，选择 “Copy as cURL (bash)”，保存到用户本机：

~~~text
/tmp/weread-request.curl
~~~

建议设置权限：

~~~bash
chmod 600 /tmp/weread-request.curl
~~~

安全要求：

- 不要把 cURL 内容、Cookie、x-wrpa-0 或其他身份头发到聊天、日志、issue 或 Git 仓库。
- agent 只检查文件是否存在、大小和权限，不输出内容。
- 不要用 bash 直接执行该文件。
- 使用 shlex.split() 解析，只允许 curl、URL、-H/--header、-b/--cookie、--compressed 等预期参数。
- 拒绝文件写入、命令替换、管道、重定向和额外 shell 语句。
- 日志只输出 HTTP 状态、业务错误、文章数量、标题、日期和分页信息；请求头和 Cookie 一律脱敏。
- 任务结束后由用户删除临时文件，或明确授权 agent 删除。

### 6. 重放和分页

1. 安全解析已保存的 cURL。
2. 先原样重放一次，确认当前会话仍然有效。
3. 保留成功请求的 Cookie、User-Agent、Referer 和动态请求头。
4. 只替换 URL 中的 bookId，第一页使用 offset=0。
5. 确认 HTTP 200，且 JSON 中没有 errCode=-2010 或其他业务错误。
6. 从真实响应中识别文章数组、总数和分页字段。
7. 优先使用响应或网页下一次请求给出的 offset；不要猜测分页步长。
8. 先限制为最多 3 页，确认契约和限频情况后再扩大回填范围。

终止条件：

- 返回空页；
- offset 或文章集合重复；
- 当前页全部是已知文章；
- 登录失效；
- 出现验证页；
- HTTP 403/429；
- 服务端返回业务错误。

建议按微信文章稳定标识（__biz、mid、idx、sn）或规范化 URL 去重。

## 工程化建议

如果接入 OS News Tracker，建议实现为独立发现源：

~~~text
account resolver
  → __biz / numeric_id / bookId
  → WeRead reader URL
  → authenticated article-list fetcher
  → normalizer
  → dedup
  → store
~~~

模块边界：

- resolver 只处理账号身份和 bookId，不接触登录凭据；
- fetcher 只从运行时安全配置读取会话，不写入来源 YAML 或业务数据表；
- __biz、bookId、公众号名和校验文章 URL 可作为非敏感审计元数据；
- 错误状态至少区分 auth_expired、not_collected、rate_limited、contract_changed 和 transport_error；
- 日常增量只读首页，遇到已知文章即停；
- 历史回填必须设置最大页数或最大文章数；
- 该端点应标记为网页内部接口，并配置契约变化检测。

## 方法边界

- 不是微信或微信读书对外发布的正式 API。
- 只能查询微信读书已收录的公众号与文章。
- 需要正常微信读书用户会话，会话可能过期或要求再次验证。
- ID 编码、动态请求头和 JSON 字段可能随前端发布变化。
- 只应低频、有界、可中止地使用，不绕过验证、限频或访问控制。
