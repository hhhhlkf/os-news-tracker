Agent 范式探索
---
一、基础推理范式
1. CoT (Chain-of-Thought)
关键特色：纯内部推理，无外部交互。通过"Let's think step by step"诱导模型生成中间步骤。
亮点：零成本提升推理能力；对算术、常识推理提升显著；是所有后续范式的基石。


2. ReAct (Reason + Act)
关键特色：思考与行动交织，每一步都可调用外部工具获取新信息再继续推理。
亮点：打破了 LLM "闭门造车"的局限；实现了 grounded reasoning；是当前主流 Agent 的默认范式。
局限：逐步贪心决策，容易陷入局部最优（短视问题）。


3. Pre-Act (Plan-then-Execute)
关键特色：将规划与执行彻底解耦。先一次性生成完整计划，再逐步执行。
亮点：避免 ReAct 的逐步贪心；全局视角更强；计划可被审核/修改后再执行。
权衡：计划可能因环境变化而失效，需要 replan 机制。


4. Reflexion
关键特色：在 ReAct 之上加入自我批评层。执行失败后，生成语言化反思，存入记忆，指导下次尝试。
亮点：实现了"从失败中学习"；无需梯度更新的自我提升；短期记忆 → 长期经验积累。


5. Code-as-Reasoning (PAL / PoT / ReCode)
关键特色：用可执行代码替代自然语言作为推理载体。LLM 生成程序，由解释器执行得到精确结果。
亮点：消除计算错误；推理过程可验证可调试；天然适合数学/数据/逻辑任务。


6. Self-Consistency
关键特色：多次独立采样 CoT 路径，通过多数投票/加权聚合选择最终答案。
亮点：利用随机性对冲单次推理的不确定性；简单有效；与任何 CoT 变体兼容。


7. Tree-of-Thought (ToT)
关键特色：将推理组织为树形搜索空间，支持 BFS/DFS + 回溯 + 剪枝。
亮点：系统性探索多条路径；可用评估函数对节点打分剪枝；适合创意/规划类任务。


8. DFSDT (深度优先搜索决策树)
关键特色：针对工具调用场景的 ToT 变体。API 调用失败时可回溯到上一决策点，换一个工具/参数重试。
亮点：解决了真实 API 的不可靠性；比 ReAct 的线性失败更鲁棒；ToolBench 上显著优于 ReAct。


二、多 Agent 范式
1. Supervisor-Worker（监督者-工人）
关键特色：中央 Supervisor 负责任务分解、分派、汇总；Worker 各自专精执行。
亮点：清晰的责任分离；Supervisor 可做质量把关；天然支持异构 Agent 池。


2. Debate / Adversarial（辩论/对抗）
关键特色：多个 Agent 持不同立场对同一问题辩论，通过对抗性讨论暴露盲点。
亮点：减少单 Agent 的确认偏误；提升事实性和推理质量；可设 Judge Agent 裁决。


3. Generator-Critic（生成-验证）
关键特色：Generator 生成候选方案，Critic 评估质量并给出改进建议，循环迭代直到满意。
亮点：分离创造与评估；Critic 可以是规则系统/测试套件/另一个 LLM；天然的质量提升循环。


4. Handoff Chain（接力链）
关键特色：Agent 按固定流水线顺序接力，每个 Agent 处理特定阶段后传递给下一个。
亮点：流程清晰可预测；每个 Agent 高度专业化；适合有明确阶段的工作流（如 RAG pipeline）。


5. Swarm / Blackboard（群体/黑板）
关键特色：无中心协调者，所有 Agent 通过共享状态板（Blackboard）读写信息，自主决定何时贡献。
亮点：高度去中心化；弹性伸缩；适合开放性、探索性任务。
挑战：协调难度大；可能出现冲突或重复工作。


6. Hierarchical Delegation（层级委派）
关键特色：多层树状结构，顶层 Agent 分解为子任务，子 Agent 可进一步向下委派，递归分治。
亮点：处理超复杂任务的自然方式；每层控制"爆炸半径"；支持任意深度的嵌套。


三、前沿趋势
1. Select-then-Solve（范式路由）
核心洞察：没有一种范式适合所有任务。一个轻量路由器先判断任务类型，再动态选择最优推理范式。
亮点数据：Oracle 路由比固定最优范式高 17 个百分点；即使训练一个简单分类器也能获得大部分收益。


2. DAG 规划器（超越线性 ReAct）
核心洞察：真实任务中工具调用存在并行机会和复杂依赖。用 DAG（有向无环图）而非线性链表达执行计划。
亮点：可自动识别并行分支；减少总延迟；GTool / Beyond ReAct 论文实测提速 2-4x。


3. 随机-确定性边界设计（Stochastic-Deterministic Boundary）
核心洞察：LLM 本质是随机系统（创造力强但不可靠），生产系统需要确定性保障。最佳架构是在两者之间画一条清晰边界。
亮点：LLM 负责"提案"（stochastic），系统规则负责"验证/约束"（deterministic）；兼顾灵活性与可靠性；是工业级 Agent 的核心设计原则。


总结对照表
|维度|核心取舍|适用场景|
|-|-|-|
|CoT vs ReAct|纯推理 vs 推理+行动|封闭问答 vs 需外部信息|
|Pre-Act vs ReAct|全局规划 vs 逐步贪心|已知流程 vs 探索性任务|
|ToT vs Self-Consistency|结构化搜索 vs 统计聚合|复杂推理 vs 简单投票|
|Supervisor vs Swarm|中心化控制 vs 去中心化|可预测流程 vs 开放探索|
|DAG vs Chain|并行优化 vs 实现简单|延迟敏感 vs 原型开发|

实际生产系统的典型组合：Pre-Act（规划）+ DAG（并行执行）+ Generator-Critic（质量循环）+ 随机-确定性边界（安全护栏）。
