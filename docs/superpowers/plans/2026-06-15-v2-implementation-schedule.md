## 二、五日实施计划

### Day 1｜用户账户系统

**功能描述**  
系统目前没有用户概念，所有人访问同一个界面。V2 引入完整的用户注册/登录体系，每人拥有独立账户，所有后续的个性化功能都以此为基础。

**交付内容**
- 邮箱 + 密码 注册和登录
- JWT 无状态鉴权（7 天有效期）
- 角色区分：普通订阅者 / 系统管理员
- 用户注册时自动初始化空偏好配置
- API：`/auth/register`、`/auth/login`、`/auth/me`

**验收标准**  
✅ 用户可注册、登录、获取当前用户信息  
✅ 未登录用户访问受保护接口返回 401

---

### Day 2｜AI 智能爬取引擎

**功能描述**  
现有系统依赖预设的 RSS 订阅和固定页面监控，对新网站无能为力。V2 引入 AI 驱动的智能爬取能力：用户只需提供网站地址和关注方向，系统自动分析页面结构、规划抓取路径、筛选高质量内容。

**核心技术亮点**
- **AI 规划**（Pre-Act 范式）：AI 分析网站链接结构，生成确定性抓取计划，防止乱跑
- **并行抓取**：多个页面同时抓取，速度提升 5–10x
- **质量评估**：AI 对每个页面打 0–10 分，低分内容自动丢弃
- **学习记忆**：系统记住哪些页面质量差，下次直接跳过，节省 LLM 调用费用
- **自适应摘要**：根据内容类型（发布说明/性能测试/技术分析）自动调整摘要格式

**交付内容**
- 用户可添加任意网站作为"智能采集源"
- 支持配置关注关键词、爬取深度、并发数量
- 运行历史记录可查看
- API：`/sources/agent`（增删改查 + 立即触发）

**验收标准**  
✅ 可新增智能采集源并触发一次采集  
✅ 采集结果正确入库，质量评分记忆功能生效

### Day 3｜个性化推荐评分 + 新闻趋势总结

#### 个性化推荐评分

**功能描述**  
不同岗位的工程师关注点不同——内核工程师关注调度器，安全工程师关注 CVE，AI 工程师关注 LLM 工具链。V2 允许每个用户定义自己的评分标准，系统对每条新闻自动算出一个 0–100 的相关度分数，Feed 默认按相关度排序。

**交付内容**
- 用户可自由创建任意数量的「评分准则」（命名 + 关键词/分类/重要度匹配 + 权重）
- 两档评分机制：
  - **快速通道**：关键词匹配算分，实时计算，无额外费用
  - **AI 精打分**（可选开启）：大模型深度理解用户关注描述，更准确
- **AI 建议准则**：系统分析当前热词 + 用户历史浏览，智能推荐评分准则
- Feed 每条信息展示相关度分数徽章（绿色≥80 / 橙色 50–79 / 灰色<50）
- API：`/users/me/profile`（读取/更新）、`/users/me/profile/suggest`

**验收标准**  
✅ 用户设置准则后，Feed 排序变为相关度优先  
✅ AI 建议准则功能返回有效建议

#### 新闻趋势总结（Digest）

**功能描述**  
面对每天大量的技术信息，管理者和决策者更需要的是「这段时间发生了什么」的全局视角。V2 提供 AI 驱动的定期总结功能，自动识别热点话题和潜在新兴趋势。

**交付内容**
- **按需生成**：用户选择时间范围（如最近 7 天），点击生成个性化总结
- **定期自动生成**：系统按配置周期（每日/每周）自动生成全局总结
- 总结内容包含：
  - 综合文字摘要（200 字以内）
  - 热点动向卡片（每个热点含原因 + 相关文章数）
  - 新兴趋势卡片（标注上升幅度）
  - 分类统计数据
- 历史总结可查看、归档
- API：`/digest`（创建/列表/详情）

**验收标准**  
✅ 点击「生成总结」后 15–40 秒内返回完整报告  
✅ 热点和趋势内容合理，与当前数据匹配

### Day 5｜群组订阅体系

**功能描述**  
当每个人都独立运行 AI 爬取时，API 成本随用户数线性增长。V2 引入群组订阅机制：有相似关注点的人组成群组，共享一套爬取任务，每个群每天只调用一次 LLM，成本由群组成员分摊。

**三级权限架构**

| 角色 | 权限 |
|------|------|
| 系统管理员 | 创建/管理群组，任命群管理员，维护全局来源池 |
| 群管理员 | 创建/删除本群，设定群爬取范围（选配 RSS + 新建 AI 来源），设置群级内容过滤，管理成员 |
| 普通订阅者 | 申请加入群组，查看群内容，设置个人打分偏好 |

> 群管理员拥有订阅者的全部权限；系统管理员拥有群管理员的全部权限。

**群级内容过滤**  
群管理员可为本群设置内容过滤规则（如「只看内核和安全相关内容，过滤招聘和活动通知」），所有成员在此基础上再叠加个人偏好。

**Feed 内容范围**  
登录用户的 Feed 只显示其所在群组订阅来源的内容，保证信息聚焦、不被噪音淹没。

**加群流程**  
用户浏览公开群列表 → 提交申请（可附理由）→ 群管理员审批 → 自动加入群组。

**按群 Digest**  
每个群可独立配置定时总结，生成仅包含本群订阅内容的趋势报告。

**交付内容**
- 群组 CRUD（系统管理员 + 群管理员均可创建）
- 成员邀请/申请/审批全流程
- 群级来源管理（RSS 选配 + AI 来源新建）
- 群级内容过滤规则配置
- 前端新增：「我的群组」页、群详情页（来源管理 + 过滤设置）、管理员群组管理页

**验收标准**  
✅ 系统管理员可创建群组并指定群管理员  
✅ 群管理员可添加来源、设置过滤规则  
✅ 普通用户申请加群并审批通过后，Feed 内容切换为群内容  
✅ 未加入任何群的用户看到引导提示而非空白页面

## 三、技术架构说明（供参考）

```
后端：Python / FastAPI / PostgreSQL
前端：React / TypeScript
AI 调用：内网 LLM 统一网关（OpenAI 兼容接口）
部署：Docker Compose（单机，内网）
```

所有 AI 调用结果均有缓存机制，重复内容不重复花费。Agent 爬取为群组层面共享，单次爬取 20 个 URL 约需 41 次 LLM 调用（冷启动），随学习记忆积累后调用次数将持续下降。
