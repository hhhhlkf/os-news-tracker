# OS News Tracker 新增功能周报

**周期：** 2026-07-03 至 2026-07-10  
**项目：** OS News Tracker（群组化 OS 技术情报平台）  
**主题：** 采集方式扩展、邮件订阅闭环、定时抓取与可配置化能力

## 一、整体进展

上周重点围绕「来源扩展」「自动化采集」「订阅分发」和「运营可配置」四个方向推进。平台在原有 RSS、页面监控、API 探测等能力之外，新增了微信搜索与微信公众号历史文章查取；同时补齐邮件订阅、定时抓取、爬取方式选中筛选、Prompt 自定义和主分类自定义等功能，使系统从手动采集工具进一步升级为可持续运行的技术情报订阅平台。

本轮新增能力已经形成较完整的链路：

```text
微信搜索 / 公众号 / 网站输入
        ↓
多源探查与爬取方式生成
        ↓
爬取方式库筛选、选中、批量执行
        ↓
Prompt 与主分类规则调整
        ↓
系统定时抓取入库
        ↓
首页筛选与邮件订阅分发
```

## 二、重点新增功能

### 1. 新增微信搜索与微信公众号查取

本周新增了面向微信生态的多源爬取能力，主要覆盖两类场景：

- **微信搜索爬取**：支持按关键词通过微信搜索入口检索文章，抓取搜索结果卡片，并对文章正文、发布时间、摘要等字段进行补抓。
- **微信公众号历史文章查取**：支持通过公众号昵称、账号标识或公众号文章链接解析账号信息，并拉取公众号近期历史文章。

实现上，微信能力已经接入 discovery 的多路由流程。普通文本可按微信搜索处理，`mp.weixin.qq.com` 链接可路由到公众号历史查取；生成的配方以 `multi_dsl` 形式保存到爬取方式库中，后续可统一启用、禁用、手动执行或纳入定时抓取。

运行过程中也补充了更细的进度事件，例如搜索开始、分页抓取、触发限流、触发验证码、文章补抓开始与结束等，方便在长耗时或网络异常场景下定位进展。

**业务价值：** 微信公众号是 OS、安全、社区动态和厂商技术文章的重要来源。本次新增后，平台不再局限于传统网页/RSS，可以覆盖更多中文技术情报来源。

### 2. 新增邮件订阅功能

本周落地了邮件任务中心，完成从新闻筛选到邮件发送的闭环。核心能力包括：

- **邮件发送**：支持基于当前筛选条件生成邮件预览，并立即发送 HTML 简报。
- **模板设置**：可保存邮件标题、收件人和筛选快照，后续重复使用。
- **预定发送**：可基于模板或独立配置创建定时邮件任务，支持启用、暂停、恢复、立即发送和发送日志查看。
- **发送通道**：后端抽象了邮件 Provider，当前支持 TOF4 与 SMTP 两类发送方式。

邮件筛选条件复用首页新闻流的过滤语义，包括关键词、主分类、信息类型、重要性、子标签、发布时间范围和排序方式。对于「最近 24 小时」「最近 7 天」「最近 30 天」这类相对时间，模板和预定任务不会固化保存当天日期，而是在真正发送时动态计算时间窗口。

后端同时记录邮件投递结果，包括触发方式、发送状态、命中文章数量、收件人、筛选快照、开始/结束时间和错误信息，便于后续审计与排障。

**业务价值：** 用户可以把常用情报筛选条件沉淀成订阅模板，通过定时邮件获得更新，不必每天手动进入系统查看。

### 3. 新增系统定时抓取功能

本周新增了系统定时抓取能力，即「系统晨抓」。该能力面向爬取方式库中的 active discovery methods 运行，不再以旧 sources 调度作为主要业务入口。

主要能力包括：

- 支持配置是否启用、运行时间、运行频率、回看窗口和巡检间隔。
- 支持手动立即运行和停止正在运行的抓取。
- 每次运行记录总方式数、成功数、失败数、入库数量、运行状态和错误信息。
- 每条爬取方式单独记录执行明细，包括 domain、发现数量、入库数量、状态和失败原因。
- 定时任务采用 tick + patrol 机制：主任务按分钟检查是否到点，巡检任务兜底补跑当天漏跑或未成功的任务。

系统晨抓执行时会复用 discovery method 的 DSL 配方，通过正常 pipeline 完成入库、去重、富集与存储。微信搜索类方式也会透传分页和补抓进度到共享运行日志，避免长任务在前端看起来像卡死。

**业务价值：** 情报采集从手动触发升级为周期性自动运行，确保新闻库持续更新，同时保留人工立即执行和停止能力。

### 4. 新增订阅源选中和筛选能力

爬取方式库侧增强了列表管理和批量操作能力：

- 支持在列表中勾选多个爬取方式后批量执行。
- 支持批量删除选中的方式。
- 支持分页展示，避免方式数量增加后列表过长。
- 支持保存页面选择和执行状态，刷新或离开页面后会自动清理陈旧的 running 状态，避免 UI 被锁住。
- 在方式详情中支持查看 DSL Recipe，并可启用、禁用或删除单个方式。

这些能力使「订阅源」从单条手动操作变成可批量管理的方式库。用户可以只选择当前关注的一批来源执行抓取，也可以将稳定方式保持 active 后交给系统晨抓自动运行。

**业务价值：** 在来源数量增长后，运营人员可以更快筛选、选择和维护订阅源，降低无效抓取和误操作成本。

### 5. 新增 Prompt 自定义功能

新增 Prompt 工作室，用于管理 discovery 和 enrichment 相关的 Prompt 套餐。

当前支持：

- 查看各阶段内置默认 Prompt。
- 新建、编辑、删除自定义 Prompt 套餐。
- 启用某一套 Prompt，启用后发现流程会优先使用该套餐。
- 停用自定义套餐，回退到系统内置默认 Prompt。
- 对 Prompt 内容进行必需 token 校验，避免误删关键变量导致流程不可用。

覆盖范围包括站点发现、推断、DSL 生成、审计、命名，以及入库富集阶段的总结和筛选 Prompt。这样当某类站点解析不稳定、候选结果筛选不准或分类口径需要调整时，可以优先通过 Prompt 边界和输出契约调整解决，减少硬编码特例。

**业务价值：** 平台的 AI 采集和筛选规则变得可运营、可迭代，非开发人员也能通过配置方式调优抓取质量。

### 6. 新增主分类自定义功能

本周新增主分类管理能力，用于维护富集阶段可用的大类标签。

主要能力包括：

- 新增主分类。
- 修改主分类名称。
- 展示每个主分类下当前条目数量。
- 删除无条目的主分类。
- 主分类改名时，同步更新历史条目的 `main_category` 字段，并合并或改名对应的主分类 Tag。

主分类会影响首页筛选、邮件模板筛选快照和富集阶段的分类选项，因此该功能让平台可以按实际业务场景调整大类口径，例如 OS 性能、安全漏洞、发行版动态、兼容性跟踪、上游社区进展等。

**业务价值：** 用户可以按业务关注的大类组织情报订阅，不需要被固定分类体系限制。

## 三、功能协同效果

本周新增功能不是孤立模块，而是组成了一条更完整的自动化情报链路：

1. 通过微信搜索、微信公众号、网站探查等方式扩展来源覆盖。
2. 将探查结果沉淀为可复用的爬取方式。
3. 通过选中、筛选和批量操作管理爬取方式。
4. 使用 Prompt 自定义调整采集、筛选和富集质量。
5. 通过主分类自定义调整订阅和展示口径。
6. 使用系统晨抓周期性执行 active 方式，保持情报库更新。
7. 使用邮件模板和预定发送，将筛选后的新闻定期推送给用户或群组。

整体上，OS News Tracker 已经从「新闻聚合看板」进一步演进为「可配置采集 + 自动运行 + 邮件分发」的技术情报工作台。

## 五、风险与后续建议

1. 微信搜索依赖外部页面和账号环境，后续需要持续观察限流、验证码和登录态失效场景。
2. 邮件预定和系统晨抓已经具备巡检补跑机制，后续可补充失败告警、重试策略和更细的通知能力。
3. Prompt 自定义能力较强，建议补充操作说明，提醒用户保留必需变量并按阶段小步调整。
4. 主分类改名会影响历史条目和订阅筛选，建议在生产环境使用前明确变更流程。
5. 邮件模板、群组订阅和主分类之间可继续增强联动，例如按群组保存默认收件人和默认筛选口径。
